# 京东独立青龙签到任务

包含 PLUS 每日盲盒、每日刮卡领豆、京喜自营店签到、金融现金签到＋双签礼包。四个入口独立启停，与 Faker 订阅分开；没有加入普通签到或种豆。金融及双签在一个入口中依次处理。保留原 Loon 脚本和手动入口。

另有每天22点的微信日报入口，可汇总 Faker 和本仓库任务及资产快照。使用专用 PushPlus 令牌，按当日最新日志保守判断，完整配置见 [微信日报说明](REPORT.md)。

此版迁移现有业务流程，使用 Node 内置模块适配 Loon，沿用已核查的官方 SDK 和活动签名逻辑，不调用第三方签名服务。尚未证明这三个活动可以仅凭 `JD_COOKIE` 自动取得全部设备参数，因此当前仍需要从手机同步活动记录。已通过模拟接口测试，NAS 实际签到结果需首次运行确认。

前三项已由用户在 NAS 实测成功。新增金融及双签已通过模拟接口和实际 AAR2 SDK 签名测试，仍需用户在青龙首次运行确认。金融使用自己捕获的登录 Cookie 和设备上下文，普通 `JD_COOKIE` 更新不会替换金融登录对。

## 已安装前三项时怎样增加金融

1. 更新 Loon「青龙任务接入」插件，保留面板地址和授权参数，执行一次「同步活动凭据」。同步结果应列出「金融签到＋双签」。沿用原金融插件已经保存的凭据；若未列出，打开原金融插件的获取开关，进入现金签到页和双签页后再同步。
2. 修改当前独立订阅的白名单为下方四项版本，依赖文件保持 `Qinglong/function/`，保存后运行一次订阅。前三个现有任务和数据继续保留。
3. 新增任务「京东金融签到＋双签礼包（独立版）」默认每天 01:00。请按你实际的普通京东签到时间调整到其后，预留随机等待和执行时间；金融入口本身不会补做普通京东签到。
4. 手动运行新增入口一次，核对金融现金、连续天数和双签京豆结果。今天金融已经签到时，仍会检查双签礼包。确认青龙运行正常后关闭原 Loon 金融自动签到，保留其手动入口。

## 1. 同步自己的凭据

更新 Loon「青龙任务接入」插件：

`https://raw.githubusercontent.com/LazingLuo/LazingLuo_Loon-Rules/refs/heads/main/Plugins/qinglong-bridge.plugin`

原来面板地址、Client ID、Secret 保留。手动操作选「同步活动凭据」，运行「青龙手动操作」。青龙环境变量中应有已启用的 `JD_COOKIE` 和 `LAZING_JD_ACTIVITY_V1`，后者是活动请求、签名环境的 JSON 包，不需要手工填写。已抓取的记录可直接同步；缺失某项时，开启该原插件的获取开关、进入相应页面后再次同步。金融需完整的现金查询和设备记录；双签页面的额外上下文一并同步，缺失时沿用原金融脚本同账号登录环境。

需要后续自动同步时，可打开「同时同步独立活动凭据」及「自动同步凭据」。手机须能访问 NAS。同步只更新凭据，不触发签到，也不重新登录京东。

## 2. 新建独立订阅

在青龙「订阅管理」新建公开仓库订阅：

| 项目 | 填写内容 |
| --- | --- |
| 名称 | 京东独立签到 |
| 链接 | `https://github.com/LazingLuo/LazingLuo_Loon-Rules.git` |
| 分支 | `main` |
| 白名单 | 见下方代码块，完整复制 |
| 黑名单 | 留空 |
| 依赖文件 | `Qinglong/function/` |
| 文件后缀 | `js` |
| 代理 | `http://mihomo:7890`，沿用当前 NAS 上 GitHub 拉取的代理 |
| 自动添加任务 | 打开 |
| 定时更新 | `0 8 * * *`，或自行调整 |

白名单原文（竖线不要加反斜线）：

```text
Qinglong/lazing_jd_(plus|scratch|jxzy|finance|report)\.js$
```

保存并运行一次订阅。全新订阅会新增四个签到入口和一个日报入口；已有任务会保留。日报需要另行填写 PushPlus 及青龙只读接入参数，并在任务命令末尾加 `now` 跳过随机等待，见 [日报说明](REPORT.md)。依赖目录中的 SDK 文件没有任务定时标记。

## 3. 首次运行与定时

先逐个手动运行一次，看青龙日志中的结果。完成、今天已领取、盲盒没有机会都会正常结束；状态不明确、凭据错误、网络错误会停止，不自动重试领取。

前三个默认时间是每天 00:02、00:07、00:12，金融默认 01:00，全部可在青龙任务编辑界面修改。命令使用普通 `task ...`，继承你现有青龙的随机延迟设置；本脚本不再加一层随机等待。若全局设为 2000 秒，各任务会分别随机等待，再启动 Node 进程，等待期间不占用活动执行锁。金融要安排在普通京东签到完成之后；前三项不能代替双签条件中的普通京东签到。

青龙实际运行正常后，请关闭对应活动的 Loon 自动签到开关，保留 Loon 手动入口。两个系统没有共享执行锁，避免同时运行同一个活动。手机已经提交过的当日记录会随活动包同步，青龙也会保留自己的提交记录，以免迁移后重复领取。金融现金和双签分别记录提交，重复执行时先查询，不会重复提交结果不明确的领取。

金融结果和双签结果分别保存到本次结果的 `status`、`doubleSign` 字段。双签接口失败或复查未确认时，任务以失败退出，但保留金融已经成功的结果；双签条件未满足时说明哪边尚未签到，不提交领取，不抹掉金融结果。

## 结果和通知

每项任务各自保存结果、历史、SDK 缓存和领取提交记录。默认目录 `/ql/data/lazing-jd/`，已挂载的 `/ql/data` 能跨容器重建保留。环境变量 `LAZING_JD_DATA_DIR` 可指定其他持久化目录。文件权限为 600，路径使用账号摘要，不直接显示账号。

日志显示成功或失败及数量、连签天数等已有信息；不会输出 Cookie、设备令牌或签名环境全文。存在青龙常用的 `/ql/data/scripts/sendNotify.js` 或同订阅根目录的 `sendNotify.js` 时使用其通知渠道；没有通知模块时，以任务日志为准，不需要为签到安装额外依赖。

遇到未登录时，在 Loon 更新并同步凭据；签名版本不兼容时按日志处理，不能仅靠更新 Cookie 修复。普通凭据更新不会清除青龙已提交记录。领取请求失败但结果不明确时，当天再次运行只查询，不重复提交。

如果 Node 被强制杀死导致残留 `running.lock`，脚本会停止并提示。确认青龙没有同项任务运行后，只清理该任务目录的 `running.lock`，保留 `state.json` 中的领取记录。

## 维护与验证

`function/jd-core.js`、`function/jxzy-core.js`、`function/jr-core.js` 分别是当前 Loon 对应源文件的固定快照，此次未更改业务逻辑。以后原 Loon 源文件更新时，需要同步核查青龙快照，不能假设二者自动联动。

离线验证：`node Qinglong/test.cjs`。测试全部使用虚构账号及模拟响应，覆盖三项已领跳过、成功领取、状态复查、网络结果不明确、跨次提交记录、同账号 Cookie 更新、Loon 提交记录导入、并发锁、超时释放、目标域名和敏感信息检查。没有调用京东真实账户接口，也没有在 NAS 上执行领取。

金融离线验证：将公开 AAR2 初始化响应保存为本地文件后，设置 `JR_AAR_INIT_FIXTURE` 指向它，再运行 `node Qinglong/finance-test.cjs`。测试真实执行内嵌 SDK 的初始化和签名，金融、双签接口全部模拟，覆盖七步完整流程、已签到后继续双签、条件不足跳过、分别保存领取记录、金融登录隔离、部分失败、超时及日志脱敏。运行时只向 `ms.jr.jd.com` 的四个指定业务接口及 `aks.jdpay.com/aar2/getJS` 发 HTTPS 请求；公开签名初始化不携带登录 Cookie。
