# 京东活动（手动）

版本 `20261026-6`。一个插件，四个手动入口，每个活动对应一个自包含脚本；无定时项，无“只参与/只领取”等额外菜单。

| 入口 | 执行范围 |
| --- | --- |
| 京喜自营 | 查询任务、计时、提交、领奖及复查 |
| 东东农场 | 查询任务、签到、提交和领取水滴；不自动浇水 |
| 天天砸金蛋 | 沿用 Faker 当前实际的 9.9 包邮任务体系，处理支持的签到和浏览任务 |
| 天天赚京豆 | 金融赚豆页任务、接取、跳转或计时领奖，最后统一复查并核对京豆明细 |

幸运转盘入口和 `Scripts/jd-wheel-activity.js` 已移除。农场固定为主农场执行模式，外部参数不能将其切换为转盘。原本机凭据、农场水滴、提交记录保留。

## 使用

更新 `Plugins/jd-activities.plugin` 后，在 Loon 手动运行对应活动。旧的独立京喜、农场/转盘插件若仍在使用，停用旧入口以免重复。原「京东合并签到」保留。

把本插件放在重叠的凭据获取规则前面。被动获取入口同时包含签到、京喜和农场等解析；主动跳过开屏配置 functionId。捕获活动模板失败时仍检查共享 Cookie。运行中的自有活动请求不会反过来覆盖捕获资料。

四个脚本复用本机同账号资料。砸金蛋和赚京豆以京东 Cookie 起步，运行时补设备参数和签名，不强制提前捕获活动页。京喜可复用同账号农场设备资料。账号绑定不符时停止。已有凭据不清空。

## 赚京豆的结果

跳转请求成功与实际到账分开显示：

- 已接取并提交跳转：请求通过，完成和到账仍待核对。
- 任务已完成，到账待确认：服务端任务状态完成，尚无匹配的收入记录。
- 今日明细确认到账 N 京豆：按活动任务名称匹配到当天的正数收入记录；金额来自收入明细。
- 今日此前已核实到账 N 京豆：本轮明细刷新失败，保留同账号当天此前已核实的记录。

汇总中的“今日到账”可以包含此前手动运行取得的京豆，“本轮提交”只统计这次提交数。例如“今日明细确认到账 6 京豆；本轮提交 0 项”表示旧任务的收入已核实，本轮没有新增提交。

明细最多读取最近三页，每页20条；按日期和任务名称匹配，排除其他活动、前一天和支出。重复分页及重复运行按收入记录去重。存在同名任务时只汇总匹配金额，单项归属保留待核对。没有匹配或查询失败时显示“到账待确认”，不会显示为“到账0京豆”。接口返回奖励和收入明细不重复累加。

明细接口参考公开 [Faker 京东资产统计源码](https://github.com/shufflewzc/faker3/blob/main/jd_bean_change.js)，使用京东官方 `https://bean.m.jd.com/beanDetail/detail.json`。只读请求；不申请奖励、不上传到第三方。仅缓存同账号当天匹配的任务名称、金额、时间和收入标识摘要，不保存完整账单。

任务列表仍沿用初始读取和最后统一复查，不在每个任务后刷新整个列表。保留服务端实际返回的错误码和经过字段遮蔽的短说明。列表查询失败与已取得的收入分别显示，明细核对不会触发任务重试。

## 执行边界

分享、邀请、购买、关注、订阅、小组件等任务留给 App。农场不浇水；不购买抽奖次数、不消耗水滴。提交前保存当天记录，结果不明确时不重复领取。再次手动运行保留此前记录，继续其他支持的任务。

Faker 的 `jd_zjindan.js` 当前查询实际走 `interact_pre_executor` 的 `bargain/task_list`，并非凭名称编造砸蛋抽奖接口。赚京豆使用 `member.jr.jd.com/member/coinQuest/coin/` 页面协议；缺省 sdkToken 按上游使用空值，跳转签名直接签原始 juid。初始化只访问京东或京东支付的官方接口，Cookie 不发送给设备/签名初始化服务。

## 文件与验证

插件：`Plugins/jd-activities.plugin`。

四个执行脚本：`Scripts/jd-jxzy-activity.js`、`Scripts/jd-farm-activity.js`、`Scripts/jd-golden-egg.js`、`Scripts/jd-earn-beans.js`。被动获取：`Scripts/jd-activity-capture.js`。

`node Tests/jd-activities.test.cjs`：71项离线检查，覆盖四个入口、转盘移除、共享资料、账号隔离、任务执行与到账区分、明细匹配/分页去重/日期隔离/缓存、失败时保留已提交结果。Apple JavaScriptCore 检查覆盖公开 SDK、手动入口和收入匹配。

手机明细已证明之前部分跳转任务实际发奖。新增明细接口在 Loon 上能否直接读取仍需手机验证；离线检查使用模拟响应，没有请求真实账号。
