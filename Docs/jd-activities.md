# 京东活动（手动）

版本20261026-9，一个插件、三个手动入口，无定时活动。

| 入口 | 范围 |
| --- | --- |
| 京喜自营 | 原有任务、领奖及复查 |
| 东东农场 | 原有任务、签到、领水滴；不自动浇水 |
| 领券中心赚京豆 | 本次抓包中的领券中心任务体系，只处理明确奖励京豆的普通浏览项 |

领券中心与已删除的Faker天天赚京豆、天天砸金蛋为不同接口，本次没有恢复两份旧脚本或幸运转盘。家电家居签到已放入合并签到插件，活动插件没有为它另设手动签到按钮。

## 获取与执行

更新活动、签到插件与脚本；若京东开屏插件在前面，也更新至20261026-5，内置相同的统一凭据获取。顺序继续为开屏、活动、签到。PLUS、京喜、农场等原凭据获取与独立存储保持兼容。

先确保Loon已取得京东Cookie，再进入领券中心打开任务列表。该原生页面的抓包只显示页面Cookie，获取脚本会复用现有京东登录Cookie，并用本页签名核对账号。活动资料仅保存在本机独立键 `JD_COUPON_ACTIVITY_ACCOUNT_V1`；不会把抓包内容内置到公开代码。随后在Loon手动运行“领券中心赚京豆”。

## 领券中心处理边界

实时读取完整任务列表，保留每项结果。仅处理列表中明确写“可获得京豆”的单次普通浏览任务；请求接取后，按服务端返回的App倒计时时长等待再提交，并重新查询任务状态。五个签名字段与抓包一致，不擅自添加时间字段。

关注、订阅、进群、分享邀请、下单、小组件、砸蛋抽奖和仅奖励抽奖机会的任务跳过。没有捕获过的签到流程也留给App；该活动页本身的签到不与家电家居签到混为一项。

每次动作先保存同账号当天记录。失败或结果不明时停止，第二次执行不重复提交这些任务。奖励数量只取 `successRewards` 中明确的京豆数量，最后复查完成标记；HTTP200不视为成功。接口返回奖励与银行式收入明细到账核对分别看待，本次没有增加京豆账单请求。

## 文件与验证

新增执行文件 `Scripts/jd-coupon-activity.js`；原京喜和农场执行继续保留。统一获取同时被签到、活动和开屏插件采用，避免首条响应脚本遮住页面凭据。

离线检查覆盖家电与京喜隔离、页面缺登录Cookie时共享账号校验、完整签到及奖励、领券中心计时和发奖、失败不重试、特殊任务跳过、原活动和PLUS凭据兼容。Apple JavaScriptCore另行检查。抓包仅离线分析，没有重放真实账号请求；手机效果待验证。
