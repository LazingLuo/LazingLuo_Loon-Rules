领券中心版本20261028-1；京喜、农场保持原版，一个插件、三个手动入口，无定时活动。

| 入口 | 范围 |
| --- | --- |
| 京喜自营 | 原有任务、领奖及复查 |
| 东东农场 | 原有任务、签到、领水滴；不自动浇水 |
| 领券中心赚京豆 | 领券中心普通倒计时浏览；分别统计京豆和砸金蛋机会 |

领券中心与已删除的Faker天天赚京豆、天天砸金蛋为不同接口，本次没有恢复两份旧脚本或幸运转盘。家电家居签到已放入合并签到插件，活动插件没有为它另设手动签到按钮。

## 获取与执行

更新活动、签到插件与脚本；若京东开屏插件在前面，也更新至20261026-5，内置相同的统一凭据获取。顺序继续为开屏、活动、签到。PLUS、京喜、农场等原凭据获取与独立存储保持兼容。

先确保Loon已取得京东Cookie，再进入领券中心打开任务列表。该原生页面的抓包只显示页面Cookie，获取脚本会复用现有京东登录Cookie，并用本页签名核对账号。活动资料仅保存在本机独立键 `JD_COUPON_ACTIVITY_ACCOUNT_V1`；不会把抓包内容内置到公开代码。随后在Loon手动运行“领券中心赚京豆”。

## 领券中心处理边界

实时读取完整任务列表，根据 assignmentType=1、shoppingActivity 项目和服务端返回的普通倒计时处理，不再要求任务描述必须出现“可获得京豆”。读小说与京东钱包等已抓到的页面路径加入浏览范围。按服务端倒计时和列表等待时间的较大值再加1秒后提交，例如本次5秒倒计时实际等待6秒；五个签名字段保持不变。

多项目浏览按未完成 itemId 逐项处理，每项完成后重新读取任务列表；已完成项目跳过。逐项保存同账号当天记录，也保留对旧版任务级记录的检查。结果未确认时，不继续该任务的下一个浏览项目。

订阅、下单、小组件、砸蛋抽奖等独立任务类型继续跳过。涉及关注、入群、邀请等标题的项目继续留待App；仅对443包已确认的“进群天天领4元叠加券”及其原页面开放普通倒计时浏览，不调用加入群聊接口。领取砸金蛋机会的普通浏览任务可处理，但不自动砸蛋，也未恢复原来删除的Faker砸金蛋和转盘脚本。

本次抓包确认：“读小说 最高赚20元”和上述群标题浏览各返回1京豆；“逛笔笔返领现金”“逛超级明星天天抽红包”各返回1次砸金蛋机会。广告名称或描述不作为实际奖励单位；以完成接口 successRewards 的京豆数组或砸金蛋机会明细分别统计。

完整列表共20项，其中15项为普通浏览任务，均已核对任务类型和项目结构，不只开放本次实际完成的4项。“新客专享免费领”实际指向看病买药频道，“浏览页面得奖励”为7个项目，养猪、快递会场、女性专区等相同类型浏览也纳入候选。运行时仍须取得无需滑动的普通倒计时、完成响应及状态复查；未实测项目的实际奖励不预先保证。另5项为签到、砸蛋抽奖、订阅、小组件和下单，本次不增加这些动作。

每次动作先保存同账号当天记录。失败或结果不明时停止，第二次执行不重复提交这些任务。京豆和砸金蛋机会分别从 `successRewards` 读取数量，不能相加为京豆。每项复查完成标记或项目状态；HTTP200不视为成功。接口返回奖励与银行式收入明细到账核对分别看待，本次没有增加京豆账单请求。
