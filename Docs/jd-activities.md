# 京东活动（手动）

一个插件，五个手动入口，每个活动对应一个自包含脚本。没有定时项、自动执行、查询/只参与/只领奖/状态等额外菜单，也不提供“一键全部”活动队列。

| 入口 | 执行范围 |
| --- | --- |
| 京喜自营 | 沿用已修好的动态任务、计时、提交、领奖流程 |
| 东东农场 | 沿用任务与奖励流程，包含已适配的农场签到；不浇水，保留全部水滴 |
| 幸运转盘 | 沿用转盘任务，使用已有免费次数；逐次复查次数，保留已确认抽奖结果 |
| 天天砸金蛋 | 依据Faker的`jd_zjindan.js`：读取当前任务、签到/浏览、提交及复查，统计实际奖励返回 |
| 天天赚京豆 | 依据Faker的`jd_jrddzjd.js`：金融赚豆页任务、接取、跳转或计时后领奖；展示数量不作为到账数量 |

京喜补充同账号共享资料回退；农场和转盘执行流程沿用现有代码。原执行锁、当天提交记录和已验证抽奖保护保留。后两项是新迁移实现，已核对公开脚本协议，尚需手机验证。

## 使用与凭据

安装 `Plugins/jd-activities.plugin` 后，停用原京喜任务、农场/转盘任务插件，避免重复入口。原「京东合并签到」继续保留，签到菜单与定时不作调整。

把活动插件放在重叠凭据获取规则前面。活动插件的被动获取入口包含现有合并签到的解析，仍会刷新签到、京喜、农场和转盘等同账号本机资料。原来的开屏诊断若排在最前，会占用该域名的大范围响应规则；获取活动凭据时将活动插件放在它前面，或暂时停用开屏诊断。活动插件主动避开四个开屏配置functionId。

- 版本 `20261026-5`：砸金蛋和赚京豆不再强制要求提前捕获活动页，优先使用本机 `JD_SIGNIN_LOGIN_V1` / `QL_BRIDGE_CREDENTIAL_V1`，也能读取农场等既有同账号 Cookie。账号绑定不符时停止。
- 京喜优先复用原资料；缺少京喜首页模板时，使用既有同账号农场等资料和已核对的公开页面参数。补充识别 `jxzy_active_task_queryTaskList`，仅进入任务列表也能保存查询资料。仍缺少共享设备资料时会明确提示。
- 新两项先复用已有签名环境；没有活动页环境时，由内置公开页面 SDK 在运行时初始化。已有不同签名版本的捕获不会原样重放。
- 缺少设备 token 时，通过京东官方 `jra.jd.com/jsTk.do` 获取；该初始化请求不带 Cookie。签名算法初始化只访问京东 `cactus.jd.com`，金融签名初始化只访问 `aks.jdpay.com`。
- 两项都使用当前京东 Cookie。金融页面地址不等于另需一份金融账号 Cookie。对照 Faker：`dylib.userInfo(cookie, 2)` 保留原 `pt_key/pt_pin`，补充 `pwdt_id`、`shshshfpb`；`jddToken` 补设备参数，`dylans.getbody` 生成签名，并没有在该调用中换取一份新的金融登录凭据。
- 本实现复用原签到/农场的公开页面 SDK 和实际接口参数，不加载 Faker 的混淆辅助程序，不复用历史 h5st、nonce、signature。Faker 辅助程序的签名实现和本版并非逐字相同，真实接口是否接受仍需手机验证。
- 活动模板解析失败时继续检查共享 Cookie，避免一种活动的解析失败阻断其他凭据获取。参数只存在本机；不清除既有凭据。

金融赚豆页面入口：`https://member.jr.jd.com/member/coinQuest/coin/`。仅提供页面位置，不在插件中自动打开或执行。

Faker的`jd_zjindan.js`当前文件名仍叫“天天砸金蛋”，实际查询走`interact_pre_executor`的`bargain/task_list`，项目ID为`3v5KsTzmzH4KqQCpjR3QQgrviq5k`，与9.9包邮任务体系有关。本版迁移这一实际流程，没有凭任务名称编造“砸蛋抽奖”接口，也不带入上游写死的首页任务ID。

## 执行结果

每项手动执行会处理支持的任务并领取相应奖励。分享、邀请、下单、关注、订阅等仍留给App；不购买抽奖机会、不消耗水滴。结果只统计领奖响应中可确认的京豆字段，任务宣传的“奖励N京豆”不算收入。未取得明确完成状态时显示“已提交，进度待App确认”。

新活动提交前写入当天记录，结果不明确时不自动重试相同提交。再次手动运行可以继续其他任务；不会因重复点击再次发起同一项有疑问的领取。各次请求更新临时API会话sdtoken，仅用于本轮同一主机，不覆盖持久登录凭据。

后两项没有真人账号联网测试；首次使用先查看日志。若提示签名初始化失败或接口拒绝，可按日志中的请求步骤继续定位，不能用离线检查通过替代手机成功。

## 文件与检查

插件：`Plugins/jd-activities.plugin`。五个执行脚本：`Scripts/jd-jxzy-activity.js`、`jd-farm-activity.js`、`jd-wheel-activity.js`、`jd-golden-egg.js`、`jd-earn-beans.js`。另有一个被动获取脚本 `Scripts/jd-activity-capture.js`，不会运行任务。

运行 `node Tests/jd-activities.test.cjs` 检查生成文件；源码目录另有 `build.py` 用于构建、`decode-static.py` 用于纯数据解码。公开发布仅包含通用脚本、插件、说明和检查，不包含上游原始研究资料、用户HAR或个人凭据。

验证记录：61项合并版离线检查通过，包含共享Cookie独立启动、仅有农场资料时京喜启动、账号隔离、两个新活动完整手动入口，以及无页面捕获时内置SDK签名。另保留原农场与京喜回归检查。签名服务和业务响应使用模拟数据，未请求真实账号接口。

## 20261026-3 修正

- 砸金蛋保留服务端下发的完整商品标识，允许 Base64 标点；缺失标识仍跳过。只有服务端未声明 `extraType` 的支持任务才使用上游明确采用的直接完成协议。
- 补齐上游请求的区域、时区和查询参数；明确只有非京豆奖励的任务按 Faker 原逻辑跳过。
- 拒绝结果显示提交阶段、接口 `code` 和 `bizCode`，任务结果不会留空，已经返回的京豆保留。服务端原文、Cookie、设备 token 和商品标识不进入通知。
- 本次手机证据：砸金蛋已经确认完成一次短视频并返回 1 京豆；赚京豆仍停在设备初始化 HTTP 400。格式修正是否足以解决 400，尚未获得更新后的手机验证，不能据离线检查宣称业务已恢复。

## 20261026-4 修正

- 手机已确认设备初始化由 HTTP 400 改为 HTTP 200；停止发生在旧版的 `if(!d.sdkToken)` 必填检查。
- 对照 Faker 的 `jd_jrddzjd.js`，设备初始化结果中的 `token`、`eid`、`sdkToken` 分别使用 `|| ""`。本版允许 `sdkToken` 缺省，使用 `{sdkToken:""}` 参与查询签名并继续请求任务列表，不把设备字段缺省等同于登录失效。
- 查询的 `deviceInfos` 仅携带对应 sdkToken；后续接取任务独立使用完整设备参数，和上游各步骤的字段用途一致。
- 日志只显示各设备字段有无及任务数量，不打印字段值。任务查询必须通过业务成功检查后才会执行任务。
