# 淘宝双11计时恢复（验证版）v0.1.0

旧的“双11赛车浏览试用版 v0.1.2”直接打开官方任务浮层页。2026-10-28 捕获的页面已升级到0.0.5，新增浮层环境检查；检查未通过时，不渲染计时组件，也不发起任务查询。0.0.4没有这道启动检查。

本插件只在原快捷指令使用的 sceneId=8917、17种 deliveryId 的独立任务HTML中，把三处官方资源目录从0.0.5改为0.0.4。旧代码仍从淘宝官方CDN下载，任务是否受理、计时多久、能否发奖仍由原官方代码及服务器处理。不会直接调用任务接口，也不提供自动滑动。

## 手机测试

1. 将插件URL加入Loon插件并开启，确认HTTPS解密已开启、证书已信任。把本插件临时排在其他改写同一任务页的插件之前。
2. 断开重连Loon；彻底退出淘宝后重新打开，让任务页重新加载。
3. 使用原来的“淘宝双11赛车浏览试用版-v0.1.2”，先选“试跑3种任务”。保持手机解锁、淘宝在前台。
4. 首次改写通知为“已切换旧版任务页”；连续改写每分钟最多通知一次。看页面下方是否恢复倒计时，最后回赛车活动核对任务次数/能量是否增加。

无需更新快捷指令，也不需要拦截HTTPDNS或添加任何IP。解密域名只增加market.m.taobao.com；不需要解密整个alicdn.com。

## 如何判断结果

- 出现倒计时且活动进度增加：此账号这几项仍接受旧计时流程。
- 有改写通知但没有计时：运行“ 双11计时恢复记录 ”查看日志，并提供任务页表现。改写通知只确认代码目录已切换。
- 没有改写记录：检查插件启用状态、规则优先顺序和market.m.taobao.com解密，可能任务页命中旧缓存。
- 页面版本或结构再次变化：脚本保持响应原样，记录原因。不会擅自适配未知版本。

测试仍无进度就停用验证插件。原生搜索页的持续滑动要求与本实验分开判断；插件不能保证服务器继续接受旧流程。

## 范围与检查

保留所有原请求参数、登录状态、页面其他资源及服务器返回，不模拟完成状态。仅保存检查次数、改写次数、时间和简短结果在Loon本机；不保存Cookie、请求完整URL或任务接口响应，不上传个人信息。
