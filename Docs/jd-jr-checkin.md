# 京东金融现金签到与双签礼包

安装 Plugins/jd-jr-checkin.plugin，开启“获取签到凭据”，进入京东金融 App 的现金签到页面。通知保存成功后关闭获取开关。无需退出登录、清空数据或重新领取已完成的签到。

先执行“京东金融手动签到”。金融今天已签到时不重复签到，但仍会检查双签礼包，符合条件则领取。已签到状态不能验证现金领取签名是否有效；需要下一天首次手动签到成功后，才建议开启“自动签到”。默认自动关闭，时间00:00，默认随机延迟0–1200秒，最小和最大秒数均可设为0–2000。等待期间不占执行锁，保留手动入口。

已用离线模拟验证签名库初始化、生成签名、先查询后提交一次再复查、缺少凭据、登录失败、网络异常、重复执行锁、随机延迟边界和本地结果读取。尚未在手机上验证首次领取。AAR2 网页签名能否替代当前 App 原生签名、捕获的设备参数在后续日期是否仍有效，需要手机实测。不会伪造签到状态或重放旧签名。

凭据、Cookie和设备参数仅写入本机 JD_JR_CHECKIN_ACCOUNT_V1，代码中没有账号数据。签名库使用京东公开 AAR2 2.1.0 SDK，获取公开初始化内容后计算新签名，不上传凭据到第三方。MITM 仅需 ms.jr.jd.com，aks.jdpay.com 的普通HTTPS初始化请求不需要解密。

最近结果：JD_JR_CHECKIN_LAST_RESULT_V1；历史最近30条：JD_JR_CHECKIN_HISTORY_V1。插件“最近结果”仅读取本地，不访问京东。首次提交前保存 JD_JR_CHECKIN_ATTEMPT_V1；即使响应超时也不会自动再次领取，应在App核实。凭据不设置固定过期天数；出现未登录再更新。

通知：签到成功显示现金数量及连续天数；已签到显示现有状态；登录类失败提示刷新凭据，其他失败查看本地日志。正在执行时的重复手动操作不会覆盖上一条结果。

离线测试：先将公开 POST https://aks.jdpay.com/aar2/getJS?version=2.1.0&name=browser 的响应存为本地文件，再设置 JR_AAR_INIT_FIXTURE 指向文件并运行 node test.cjs。测试以模拟接口代替签到接口，不发送真实签到请求。

## 双签礼包

金融签到成功、已签到或领取返回成功后，查询双签页面。只有京东及京东金融均已签到、礼包尚未领取且状态日期为当天时，才提交一次领取，再查询页面确认。不会替用户补做京东签到，也不处理双签页面中的推广任务。

默认复用同账号的金融登录Cookie，查询、领取参数来自356抓包；不包含抓包里的账号信息。若双签查询失败，开启“获取签到凭据”，进入金融App双签礼包页面一次，保存其页面环境后关闭。这个捕获可在今天已经领奖后完成，无需重复领取。双签领取请求是否能直接复用金融登录环境，仍需手机首次运行验证。

金融签到通知附加双签状态，成功显示京豆数量，条件未满足说明哪边尚未签到。金融签到与双签结果分别记录，双签失败不会覆盖金融签到成功状态。插件“最近结果”只读本地，不会触发领取；“手动签到”会在处理金融签到后检查并领取符合条件的双签礼包。

双签提交记录：JD_JR_DOUBLE_SIGN_ATTEMPT_V1；详细结果位于最近结果和历史的doubleSign字段。提交前保存当天账号记录，网络超时、返回异常、复查未确认均不自动再次领取。若第一次运行早于京东签到完成，会报告条件未满足，可在京东签到完成后手动执行金融签到入口再检查。
