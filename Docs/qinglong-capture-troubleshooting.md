# 青龙接入：没有凭据获取记录时怎样排查

2026-10-17.3修复一处触发规则缺口：旧规则要求`functionId`出现在URL中。接口编号仅位于POST表单正文时，请求不会进入凭据获取脚本，脚本任务中也就没有这条记录。这个问题由代码和模拟请求确认；具体手机是否恰好遇到它，需要更新后核对。

## 本次修改

京东和京喜在`api.m.jd.com/api`、`api.m.jd.com/client.action`的成功POST响应会进入本地识别入口，再从URL查询参数及表单正文读取接口编号。只保存原来允许的日常登录、签到、刮卡、PLUS及京喜接口；不把任意成功响应都当成有效凭据。编号冲突、重复或编码异常时保留原凭据。金融和双签原有触发规则、登录隔离及每4小时同步保持原样。

没有改写手机发出的请求。为复用原解析器，只在脚本内部复制的请求对象上补齐接口编号。获取只写手机本地记录，不请求NAS、不签到、不领取、不上传。没有新增凭据、令牌或账号通知。

## 手机上需要更新哪里

1. 在Loon更新「青龙任务接入」插件。更新青龙/NAS的仓库订阅不会更新手机插件。
2. 插件内打开「日常获取京东凭据」；需要独立任务模板时，同时打开「获取独立活动凭据」。
3. 确认Loon的MITM及脚本功能已开启，MITM证书已安装并受信任，插件有效主机包含`api.m.jd.com`和`ms.jr.jd.com`。插件本身也须启用。
4. 重新打开京东，进入普通签到、刮卡或PLUS页。只需要进入页面触发查询，不要求再点领取。
5. 在Loon「脚本任务」查看「青龙京东与京喜凭据获取」。金融查看「青龙金融与双签凭据获取」。
6. 「青龙任务接入」→「手动操作」→「最近凭据获取结果」，再运行「青龙手动操作」。新记录的`version`为`2026-10-17.3`；`functionIdSource`为`url`、`body`或`url_and_body`，表示识别位置。只显示接口、时间、更新类型和状态，不显示账号或凭据。
7. 确认本地记录确实刷新后，再选择「同步活动凭据」并运行「青龙手动操作」。同步会更新已有京东登录凭据及可用的独立活动记录，不重新登录京东，也不能使服务器已失效的旧Cookie恢复有效。

本插件不是所有京东请求的通用Cookie采集器；日常登录仍只接受原白名单的`startup`、`logConfig`、`queryPagePopWindow`、`babelGetGuideTips`等已知成功请求及对应活动查询。如果脚本任务已出现，但记录显示未保存，应根据记录检查接口是否通过成功状态、账号一致性和模板完整性验证。

如果更新后仍完全没有脚本记录，应核对请求记录中是否出现上述主机的完整HTTPS URL：仅看到`主机:443`的TCP连接时，尚未得到可供响应脚本解析的HTTP请求。凭据获取记录和同步记录是两条流程，NAS连接正常不能证明手机捕获规则已经触发。

## 验证范围

21项统一获取检查和18项青龙接入检查通过。全部使用虚构凭据及模拟响应，覆盖正文接口编号、URL接口编号、两处一致、冲突/重复/异常编码、未登录响应不覆盖、账号隔离和无网络副作用。未访问用户手机或NAS，不代替手机实际触发验证。
