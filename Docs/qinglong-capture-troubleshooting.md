# 青龙接入：没有凭据获取记录时怎样排查

2026-10-17.3修复一处触发规则缺口：旧规则要求`functionId`出现在URL中。接口编号仅位于POST表单正文时，请求不会进入凭据获取脚本，脚本任务中也就没有这条记录。这个问题由代码和模拟请求确认；具体手机是否恰好遇到它，需要更新后核对。

## 与京东开屏配置检测共用时的冲突

Loon同一响应只执行第一条命中的Response Script。[官方匹配规则](https://nsloon.app/docs/Script/script_v2/#http-第一条命中)说明Request和Response各自最多选择一条。开屏插件的「京东开屏配置探测」覆盖了京东API，若排在前面，正常的startup、logConfig等响应会由探测脚本处理，青龙获取脚本不会再执行。单独更新青龙代码或反复同步不能解除这个冲突。

当前建议：在Loon「京东开屏处理」只关闭「配置检测」，保留整个开屏插件，以及start推迟、图片尺寸拒绝和视频拒绝。再打开京东，查看青龙获取记录，确认刷新后同步。此操作会暂停只读配置线索收集，不影响独立的start、图片、视频处理规则。金融API走另一主机，不受这条京东探测规则占用。

青龙插件同时排除了URL中`functionId=start`的响应，避免调整插件顺序后抢占start处理。没有把整个青龙插件移到开屏插件前面；两套广泛响应规则在同一API上不能靠顺序实现同时执行。需要同时保留API配置探测和凭据获取时，须统一调度，当前版本没有宣称已实现双脚本串联。

本机私有HAR离线回放已验证：在没有其他响应脚本抢占时，startup和logConfig两条请求能更新手机登录记录。回放没有发送网络请求，没有公开HAR或Cookie；这只证明保存逻辑可运行，不证明该Cookie的服务器登录状态已恢复。

## 本次修改

京东和京喜在`api.m.jd.com/api`、`api.m.jd.com/client.action`的成功POST响应会进入本地识别入口，再从URL查询参数及表单正文读取接口编号。只保存原来允许的日常登录、签到、刮卡、PLUS及京喜接口；不把任意成功响应都当成有效凭据。编号冲突、重复或编码异常时保留原凭据。金融和双签原有触发规则、登录隔离及每4小时同步保持原样。

没有改写手机发出的请求。为复用原解析器，只在脚本内部复制的请求对象上补齐接口编号。获取只写手机本地记录，不请求NAS、不签到、不领取、不上传。没有新增凭据、令牌或账号通知。

## 手机上需要更新哪里

1. 在Loon更新「青龙任务接入」插件。更新青龙/NAS的仓库订阅不会更新手机插件。
2. 插件内打开「日常获取京东凭据」；需要独立任务模板时，同时打开「获取独立活动凭据」。若同时启用了「京东开屏处理」，先关闭它的「配置检测」，解除同一响应只执行一条脚本的冲突。
3. 确认Loon的MITM及脚本功能已开启，MITM证书已安装并受信任，插件有效主机包含`api.m.jd.com`和`ms.jr.jd.com`。插件本身也须启用。
4. 重新打开京东，进入普通签到、刮卡或PLUS页。只需要进入页面触发查询，不要求再点领取。
5. 在Loon「脚本任务」查看「青龙京东与京喜凭据获取」。金融查看「青龙金融与双签凭据获取」。
6. 「青龙任务接入」→「手动操作」→「最近凭据获取结果」，再运行「青龙手动操作」。新记录的`version`为`2026-10-18.2`；`functionIdSource`为`url`、`body`或`url_and_body`，表示识别位置。只显示接口、时间、更新类型和状态，不显示账号或凭据。
7. 确认本地记录确实刷新后，再选择「同步活动凭据」并运行「青龙手动操作」。同步会更新已有京东登录凭据及可用的独立活动记录，不重新登录京东，也不能使服务器已失效的旧Cookie恢复有效。

本插件不是所有京东请求的通用Cookie采集器；日常登录仍只接受原白名单的`startup`、`logConfig`、`queryPagePopWindow`、`babelGetGuideTips`等已知成功请求及对应活动查询。如果脚本任务已出现，但记录显示未保存，应根据记录检查接口是否通过成功状态、账号一致性和模板完整性验证。

如果更新后仍完全没有脚本记录，应核对请求记录中是否出现上述主机的完整HTTPS URL：仅看到`主机:443`的TCP连接时，尚未得到可供响应脚本解析的HTTP请求。凭据获取记录和同步记录是两条流程，NAS连接正常不能证明手机捕获规则已经触发。

## 验证范围

22项统一获取检查和18项青龙接入检查通过；额外的私有京东HAR回放检查也已通过。全部使用虚构凭据及模拟响应，覆盖正文接口编号、URL接口编号、两处一致、冲突/重复/异常编码、未登录响应不覆盖、账号隔离和无网络副作用。未访问用户手机或NAS，不代替手机实际触发验证。
