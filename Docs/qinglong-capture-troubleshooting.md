# 青龙接入：没有凭据获取记录时怎样排查

## 与京东开屏插件配合

2026-10-18精简版「京东开屏处理」只匹配`client.action?functionId=start`，将展示时间推迟到2099年，并在实际修改后通知。配置检测、图片尺寸处理及视频拦截已移除。

青龙获取规则继续排除`functionId=start`。正常的`startup`、`logConfig`和签到请求由凭据获取入口识别，两者可同时启用。旧版开屏插件曾用广泛API响应规则检测配置，会占用凭据获取所需的响应；请更新开屏插件。若还单独安装了旧「京东开屏配置探测（临时）」插件，也请删除。

## 手机上需要更新哪里

1. 更新Loon「青龙任务接入」与「京东开屏处理」插件。青龙/NAS仓库订阅不会更新手机插件。
2. 在青龙接入中打开「日常获取京东凭据」；需要独立签到模板时，同时打开「获取独立活动凭据」。
3. 确认Loon脚本与MITM已开启、证书已安装并受信任，青龙插件有效主机包含`api.m.jd.com`和`ms.jr.jd.com`。
4. 重新打开京东，进入普通签到、刮卡或PLUS页，触发页面查询。金融进入金融签到及双签页面。
5. Loon「脚本任务」中查看「青龙京东与京喜凭据获取」或「青龙金融与双签凭据获取」。
6. 「青龙任务接入」→「手动操作」→「最近凭据获取结果」，再运行「青龙手动操作」。`functionIdSource`表示接口编号来自URL、表单正文或两处一致。这里只显示接口、时间和保存状态。
7. 确认手机记录刷新后，再执行「同步活动凭据」。同步更新已有京东登录及可用的独立活动记录，不重新登录，也不能让服务端失效的旧Cookie恢复有效。

## 识别范围与验证

京东及京喜在`api.m.jd.com/api`、`api.m.jd.com/client.action`的成功POST响应进入本地识别，再从URL及表单读取接口编号。只有白名单接口、成功状态、同账号及完整模板通过验证后才保存。接口编号冲突、重复或编码异常时保留原凭据。金融登录仍与普通京东登录分开保存，每4小时同步规则保持原样。

凭据获取只写手机本地，不请求NAS、不签到或领取、不计算签名、不自动上传，也不改写手机的实际请求。凭据获取和同步是两个步骤；NAS连接正常不能证明手机捕获已经触发。

若完全没有脚本记录，检查是否仅看到`主机:443`的TCP连接，还是已有完整HTTPS请求；再检查其他插件是否也匹配相同响应。若已有脚本记录但未保存，则根据最近获取结果核对成功状态、账号及模板完整性。

本地22项统一获取检查、18项青龙接入检查，以及start规则与凭据获取互不占用的检查通过。测试使用模拟请求，不访问手机或NAS。本机抓包可通过`node Tests/qinglong-credential-capture.test.cjs --jd-har /自己的文件.har`离线回放，不打印凭据。
