# 淘宝 Orange 配置观察

版本：2026-10-25.1。供淘宝 iPhone 10.68.0 的开屏配置排查使用。当前是观察工具，尚未验证手机能捕获目标配置，不承担去广告操作。

## 做什么

MITM 仅追加两个静态分析确认的配置主机：`orange-dc.m.taobao.com`、`dorangesource.alicdn.com`。观察这些主机的 HTTP/已解密 HTTPS 请求与响应；若解密后 URL 仍是 IP，则要求 HTTP Host 明确属于这两个主机。

请求脚本只在 Header 阶段计数，不读取请求正文。响应脚本始终以 `$done({})` 保留原内容，不改时间、广告素材、响应状态、缓存、压缩协商或网络调度。没有 DNS、AMDC、IP 拒绝或 UDP 修改规则，也不主动发请求。

只在本机保存累计次数、北京时间、两个固定主机名、固定结果文字、六项已知布尔/整数开关及紧急禁用素材的数量。素材 ID、Cookie、签名、账号、设备号、完整 URL、请求头、正文及其他配置均不保存或输出。正文仅临时检查，单条检查上限 512 Ki 字符；JSON 层级、节点数和嵌套解码总长度均有限制。超过限制原样放行。

目标组为 `ios_bootimage_client`、`bootimage_emergency`。只看到组名与真正看到可识别的设置分开计数；后者要求设置处于明确的目标组上下文，且是已知字段的布尔值或整数。静态模型字段并非已经验证的真实下发格式，因此真实配置格式不同可能只有组名记录。

## 测试步骤

1. 安装本插件，保持已有可信任的 Loon MITM 证书。测试时关闭先前的“淘宝开屏时间改写（验证版）”和“淘宝开屏拦截与命中通知”，便于观察。无需卸载淘宝、屏蔽 DNS、修改 TLS 指纹或禁用 UDP 443。
2. 保存插件，关闭再开启 Loon 隧道；手动运行一次“清空Orange检查记录”。
3. 正常打开淘宝、刷新首页、打开一个商品。可以正常切换后台再回来，**不需要等广告出现**。
4. 到 Loon 手动运行“Orange检查结果”，查看请求、响应、开屏组名、开屏设置和最近结果。若当前没有请求，可保留插件随日常使用观察；不要靠连续杀进程或重装强制请求。

若淘宝网络加载异常，关闭这个观察插件并重连隧道，恢复本次增加的 MITM 范围。其余设置保持原样。

## 结果怎么理解

| 结果 | 含义 |
|---|---|
| 请求和响应均为 0 | 这套观察规则尚未见到目标流量；可能尚未请求、被其他规则先处理，或使用无法识别/解密的通道 |
| 有请求、响应为 0 | 请求观察脚本执行过，响应观察脚本尚未执行；不能只据此判断服务器未返回 |
| 有响应、开屏组名为 0 | 确实看到了配置服务的响应，这次没有识别到目标组；同时检查状态及正文格式提示 |
| 看到开屏组名，尚无可识别的设置 | 可能只有索引或格式不适配，不能当作已获得开屏开关值 |
| 找到开屏设置 | 在明确的目标组内读到了已知布尔/整数值，可据此继续分析；**原内容仍完整保留，广告尚未被关闭** |

“收到配置响应”和“找到开屏设置”各自每小时最多一次自动通知。每次手动“Orange检查结果”都会显示通知。查询记录不联网。

Loon 每个请求/响应阶段最多执行一条匹配脚本；若其他插件先占用了目标请求或改写其 Body，此观察脚本可能不执行。详情中的 modifiedResponse 等通用标记不能代替本插件的检查记录。

## 文件及验证边界

- `Scripts/taobao-orange-probe.js`：通用观察脚本。
- `Plugins/taobao-orange-probe.plugin`：仓库安装入口。
- `Docs/taobao-orange-probe.md`：本说明。
- `Tests/taobao-orange-probe.test.cjs`：离线模拟检查。

本地同目录入口为 `taobao-orange-probe-local.plugin`，引用同目录脚本。仓库入口引用 main 上的远程脚本，发布前该链接不可用于安装。

离线用例按静态模型构造，只验证观察、范围、通知和原内容保留，不证明真实淘宝下发格式兼容。当前没有手机捕获目标响应或去开屏效果验证。

语法依据：https://nsloon.app/docs/Script/script_v2/ 和 https://nsloon.app/docs/Plugin/ 。
