# 青龙任务接入

先在 NAS 安装青龙，在系统设置的应用设置中建立应用，授予环境变量和定时任务权限。Loon 3.5.1(983) 或更新版本可使用此插件。

1. 导入 `Plugins/qinglong-bridge.plugin`。
2. 在插件参数中填写自己的青龙面板地址、Client ID、Client Secret。模板均为空；个人凭据不上传 GitHub。
3. 手机连到 NAS 所在局域网。在插件「手动操作」选择「检查连接」，然后运行脚本「青龙手动操作」。连接成功只证明接口和读取权限正常，不表示签到成功。
4. 选择「同步京东凭据」，再执行同一入口。已有三合一签到记录时读取最新同账号登录对；否则保持「日常获取京东凭据」打开，正常使用京东或进入签到页面后再同步。
5. 青龙的环境变量页面应出现 `JD_COOKIE`。同账号更新，其他账号保留；同账号有重复变量时停止。禁用的变量保持禁用，需在面板确认后手动启用。
6. 添加选定的活动脚本和任务后，用「列出任务」查看数字 ID。填写一个「指定任务ID」，再选择「执行指定任务」。每次只触发这个现有任务，不创建脚本、不运行任意命令。接口接收请求不等于活动成功，最终看青龙任务日志或通知。

可开启「自动同步凭据」每4小时尝试更新，按手机本地时间在每天0、4、8、12、16、20点整执行。离开家后局域网地址不可达，同步会失败，等重新连接后可手动同步或等待下一次。NAS 自己的定时任务独立运行，不依赖 Loon 到点在线。同步成功不表示延长了凭据有效期。

使用本仓库独立的 PLUS 盲盒、每日刮卡、京喜自营、金融签到＋双签青龙任务时，在手动操作中选择「同步活动凭据」并执行，会同时同步 `JD_COOKIE` 及 `LAZING_JD_ACTIVITY_V1`。活动变量只含这些活动已有的请求和签名环境、领取提交记录；不导出全部 Loon 数据、不含青龙 Client Secret。金融额外同步完整的现金签到查询、设备参数、双签页面上下文以及现金和双签各自的提交记录，金融登录对独立保留，不用普通京东 Cookie 替换。只存在某些活动记录时会先同步已有记录，缺失的活动须开启原插件获取开关并进入对应页面后再同步。若同时存在不同账号的活动记录，本次停止，需先核对本机账号。

「同时同步独立活动凭据」默认关闭。打开后，普通手动同步及每4小时自动同步也会同步这些活动记录。Faker 任务仍读取原来的 `JD_COOKIE`，不使用新活动变量。登录凭据和活动变量是两次独立写入；后者失败时会明确报告部分成功，需查看面板后重新同步。禁用的变量保持禁用，不会自动启用。

初次同步绑定账号。更换账号需要先清除本插件 `QL_BRIDGE_ACCOUNT_V1`、`QL_BRIDGE_CREDENTIAL_V1` 两个记录并确认原三合一插件的账号。插件只读已有三合一凭据，不修改原签到插件。

本插件不重新登录京东、不生成 pt_key、不发送京东签到请求。凭据捕获仅写手机本地；主动同步只发送到配置的青龙地址。不跟随 HTTP 跳转，HTTP 地址限制为局域网 IPv4 或 localhost；远程地址需 HTTPS。个人配置、Loon 持久化导出和面板数据均可能含密钥，请勿公开。

捕获、手动同步和任务触发分别有独立入口条件。自动同步开关默认关闭，不会因打开京东而触发青龙活动。写请求失败不自动重试；先查青龙状态，避免不确定结果时重复提交。

青龙接口依据：`whyour/qinglong` 的 `back/api/open.ts`、`back/api/env.ts`、`back/api/cron.ts`。Loon 参数采用官方插件对象传参语法，不依赖拼接带密钥的 JSON 字符串。
