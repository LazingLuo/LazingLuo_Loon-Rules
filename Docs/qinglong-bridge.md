# 青龙任务接入

先在 NAS 安装青龙，在系统设置的应用设置中建立应用，授予环境变量和定时任务权限。Loon 3.5.1(983) 或更新版本可使用此插件。

2026-10-21 更新：自动同步改为每天 **0点、10点、16点**。保留现有自动同步开关和面板参数。

同步通知标题为“同步成功”或“同步失败”，正文逐项列出 `JD_COOKIE`、刮卡凭据、PLUS盲盒凭据、京喜凭据、金融凭据、金融双签凭据的“新增／已更新／无变化”。只列本次涉及的项目；任务提交记录有更新时单独显示“任务记录：已更新”。变化按当前青龙值比较，忽略抓取时间和对象字段顺序；金融与金融双签分别比较。每次同步成功都发通知，相同原因的连续自动同步失败保持原来的静默处理。变量禁用状态保留并简短标注。

示例：

```text
同步成功
JD_COOKIE：已更新
京喜凭据：无变化
金融凭据：已更新
金融双签凭据：无变化
```

1. 导入 `Plugins/qinglong-bridge.plugin`。
2. 在插件参数中填写自己的青龙面板地址、Client ID、Client Secret。模板均为空；个人凭据不上传 GitHub。
3. 手机连到 NAS 所在局域网。在插件「手动操作」选择「检查连接」，然后运行脚本「青龙手动操作」。连接成功只证明接口和读取权限正常，不表示签到成功。
4. 选择「同步京东凭据」，再执行同一入口。已有三合一签到记录时读取最新同账号登录对；否则保持「日常获取京东凭据」打开，正常使用京东后再同步。
5. 青龙的环境变量页面应出现 `JD_COOKIE`。同账号更新，其他账号保留；同账号有重复变量时停止。禁用的变量保持禁用，需在面板确认后手动启用。
6. 添加选定的活动脚本和任务后，用「列出任务」查看数字 ID。填写一个「指定任务ID」，再选择「执行指定任务」。每次只触发这个现有任务，不创建脚本、不运行任意命令。接口接收请求不等于活动成功，最终看青龙任务日志或通知。

本插件已统一获取普通签到、每日刮卡、PLUS 盲盒、京喜自营、金融现金签到和双签页面凭据。更新插件后可禁用原来的「京东每日自动签到」「京喜自营每日签到」「京东金融现金签到」三个 Loon 插件，NAS 上的任务不受影响。

- 「日常获取京东凭据」：从指定成功请求获取普通京东登录 Cookie，默认开启。
- 「获取独立活动凭据」：进入对应活动页面时保存或刷新该活动的请求模板、签名环境或金融设备参数，默认开启。无需启用原签到插件；金融和双签仍需进入各自页面。查询、页面签名环境及设备参数可能来自不同请求，尚未齐全时日志中的完整状态为 false。
- 「同时同步独立活动凭据」：决定普通手动同步和每天0、10、16点自动同步是否同时上传活动记录，保留原来的设置。手动选择「同步活动凭据」时会直接上传已有活动记录。

获取只写手机本地，不连接 NAS、不自动触发签到或领取，不计算签到签名。金融 Cookie 与普通京东 Cookie 独立保存。已有本地活动记录、青龙环境变量格式和提交保护记录保持兼容。原插件自带的手动入口仍可按需重新启用；合并不包含种豆插件，种豆若仍由 Loon 执行须单独保留。

本地查看获取情况：手动操作选择「最近凭据获取结果」，再运行「青龙手动操作」。此入口无需连接 NAS，也不要求填写 Client ID / Secret。输出时间、接口名称、更新类型和完整状态；不输出 Cookie、账号、设备令牌或请求原文。获取日志位于「青龙京东与京喜凭据获取」「青龙金融与双签凭据获取」。诊断记录为 `QL_BRIDGE_CAPTURE_LAST_V1`，最近30条为 `QL_BRIDGE_CAPTURE_HISTORY_V1`；查看获取结果不覆盖上次同步结果。获取默认不重复发送通知，以日志和本地记录判断是否刷新。

可开启「自动同步凭据」，按手机本地时间在每天0、10、16点整执行。离开家后局域网地址不可达，同步会失败，等重新连接后可手动同步或等待下一次。NAS 自己的定时任务独立运行，不依赖 Loon 到点在线。同步成功不表示延长了凭据有效期。

2026-10-19 修正：Cron 字面量须写为 `cron "0 */4 * * *" then script(...)`。此前漏了引号，可能导致定时项未注册；JavaScript 的手动同步仍可正常运行。此次仅修正定时声明，未修改同步、凭据捕获或任务执行逻辑。依据为 Loon Script v2 官方文档：https://nsloon.app/docs/Script/script_v2/ 。

如果整点附近「脚本任务」没有同步运行记录，先到插件参数确认「自动同步凭据」已打开、保存并重载配置，再到定时脚本列表确认「京东凭据同步到青龙」存在且已启用。不要把截图中的「青龙京东与京喜凭据获取」当作同步记录；捕获只写手机本地。截图不能单独确认是否未注册或到点未被调度，修复后仍需实际触发验证。更新已有插件时保留原面板参数；不要删除原配置或公开填写过密钥的插件。

使用本仓库独立的 PLUS 盲盒、每日刮卡、京喜自营、金融签到＋双签青龙任务时，在手动操作中选择「同步活动凭据」并执行，会同时同步 `JD_COOKIE` 及 `LAZING_JD_ACTIVITY_V1`。活动变量只含这些活动已有的请求和签名环境、领取提交记录；不导出全部 Loon 数据、不含青龙 Client Secret。金融额外同步完整的现金签到查询、设备参数、双签页面上下文以及现金和双签各自的提交记录，金融登录对独立保留，不用普通京东 Cookie 替换。只存在某些活动记录时会先同步已有记录，缺失的活动须开启本插件「获取独立活动凭据」并进入对应页面后再同步。若同时存在不同账号的活动记录，本次停止，需先核对本机账号。

「同时同步独立活动凭据」默认关闭。打开后，普通手动同步及每天0、10、16点自动同步也会同步这些活动记录。Faker 任务仍读取原来的 `JD_COOKIE`，不使用新活动变量。登录凭据和活动变量是两次独立写入；后者失败时会明确报告部分成功，需查看面板后重新同步。禁用的变量保持禁用，不会自动启用。

初次同步绑定账号。更换账号需要先清除本插件 `QL_BRIDGE_ACCOUNT_V1`、`QL_BRIDGE_CREDENTIAL_V1` 两个记录并确认原三合一插件的账号。获取入口只接受已绑定的同账号凭据，账号不一致时保留原记录。

本插件不重新登录京东、不生成 pt_key、不发送京东签到请求。凭据捕获仅写手机本地；主动同步只发送到配置的青龙地址。不跟随 HTTP 跳转，HTTP 地址限制为局域网 IPv4 或 localhost；远程地址需 HTTPS。个人配置、Loon 持久化导出和面板数据均可能含密钥，请勿公开。

捕获、手动同步和任务触发分别有独立入口条件。自动同步开关默认关闭，不会因打开京东而触发青龙活动。写请求失败不自动重试；先查青龙状态，避免不确定结果时重复提交。

青龙接口依据：`whyour/qinglong` 的 `back/api/open.ts`、`back/api/env.ts`、`back/api/cron.ts`。Loon 参数采用官方插件对象传参语法，不依赖拼接带密钥的 JSON 字符串。

离线验证：`node Tests/qinglong-credential-capture.test.cjs` 和 `node Tests/qinglong-bridge.test.cjs`。统一获取脚本由 `node Tools/build-qinglong-capture.cjs` 生成，复用现有活动解析器；修改解析器后须重新生成。可用 `--har /自己的文件.har` 在本机回放请求，测试不发送网络请求，不将 HAR 或账号数据写入仓库。
