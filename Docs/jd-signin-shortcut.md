# 京东全部签到 · 快捷指令调用Loon v0.1.0

一个快捷指令，依次调用Loon完成现有11项签到。Cookie和页面资料留在Loon里，读取、签名、请求与提交记录都由Loon处理。

## 包含项目

普通签到 → 每日刮卡 → PLUS盲盒 → 种豆礼包 → 京喜签到 → 金融签到＋双签 → hs签到 → ys签到 → 天天领豆 → 互动游戏签到 → 家电家居签到。

金融双签跟在金融签到后，共11项、12种签到／礼包结果。只执行原有签到范围，不处理农场、转盘、京喜浏览、领券中心等活动。

## 安装：只使用远程插件订阅

这次统一采用远程插件订阅：不用复制JS到iCloud，不用修改主配置，也不用添加“本地脚本”规则。原来的本地安装说明不再作为推荐方式。

下载并解压私人配套的「京东全部签到-订阅安装包-v0.1.0.zip」，里面只有已签名快捷指令、`本机配对码.txt`和说明。

1. 在Loon的插件管理中添加下面的订阅地址，并启用插件：

   `https://raw.githubusercontent.com/LazingLuo/LazingLuo_Loon-Rules/refs/heads/main/Plugins/jd-signin-shortcut.plugin`

2. 打开新插件的参数设置，找到 **“本机配对码”**。打开私人安装包的 `本机配对码.txt`，复制整行，粘贴到这一项；保留中间的竖线，保存。这里只填这行配对码，不填Cookie。
3. 导入同一私人安装包里的 `京东全部签到-v0.1.0.shortcut`。保存Loon设置并断开重连，再运行快捷指令。

插件已经包含所需的请求规则和 `DOMAIN,example.com,DIRECT`，JS直接从仓库下载。以后在Loon更新插件／脚本即可，不需要重新复制文件。只要配对码不变，已有快捷指令继续使用。

如果已经按照之前的 `主配置追加.txt` 加了那两条桥接规则，改用订阅版时只删除那两条重复的桥接规则；没有加过就不用动主配置。原来的京东签到和凭据获取规则保留。

保留目前负责获取京东凭据的签到／活动／开屏插件。这一版没有新增凭据获取规则，也不需要增加MitM域名。旧的Cookie导出测试和美团助手使用不同路径，可以保留。

## 运行

保持Loon连接、手机解锁，运行“京东全部签到-v0.1.0”。不需要先选择Cookie文件，也不需要安装Scriptable、访问NAS或使用SSH。

每项返回后显示简短进度通知，最后弹出全部结果。已有资料可以直接沿用；缺少某项资料时，该项提示“缺少凭据”，随后继续其他项目。PLUS盲盒和金融仍使用原来的专用资料，不以普通Cookie替代。

任务间默认随机等5—15秒。需要调整时，编辑快捷指令，修改开头标记为“任务间等待上限（秒）”的文本 `15`：可填5—120的整数，`0`表示不等待。本参数只管理本次快捷指令，原有定时签到参数保持原样。

## 中断与结果

- 每次本机调用只执行一项签到，避免把整队签到放进一次长请求。单项预算45秒，Loon入口55秒；超时后记为结果待确认，并禁止这一调用继续发送请求。
- 单项接口失败、缺资料或状态待确认，会保留结果并继续后续项目。手机到Loon的调用发生网络错误时，快捷指令可能停止；20分钟内重新运行会继续这一轮，已返回的步骤读取原结果。
- 某一调用中断、没有返回结果时，不自动重发该项。显示“上次运行中断，结果待App确认”，再继续其他签到。
- 继续使用原签到的当天提交记录。查询已完成时不会为了显示数量再领取；奖励只取原接口返回的数量，不把HTTP200当作签到成功。
- 与原合并签到共用执行锁。快捷指令执行期间，原来的手动／自动队列会提示正在执行；没有新增自动任务。原定时项是否启用仍由你原来的配置决定。
- 换账号、跨零点、本地保存失败、执行锁变化或超出这一轮的20分钟时限，会停止调用。被中断的锁会在短暂租期后失效，避免一直占住签到入口。

需要回看时，在Loon手动运行 **“查看快捷指令签到结果”**。这只是读取最近结果，不会再次签到。
