# 东东农场与幸运转盘：Loon 手动版

按用户 407、408 抓包和京东当前公开农场前端接入，使用当前任务平台接口，不依赖 Faker3。运行时查询农场任务、补充模块和幸运转盘任务，合并后完整显示服务器返回的列表。任务名称、任务次数和浏览时长均读取服务器，不写死某一天的任务列表。

## 安装与获取凭据

远程安装文件：`Plugins/jd-farm-tasks.plugin`。需要同时发布 `Scripts/jd-farm-tasks.js` 与 `Scripts/jd-farm-tasks-capture.js`。

本地安装：将本目录两个 JS 文件导入 Loon 本地脚本，再导入 `jd-farm-tasks-local.plugin`；必要时在插件内选择同名本地脚本。

1. 安装插件，保持“获取农场与转盘凭据”开启，并启用 Loon MITM、安装和信任对应证书；插件只增加 `api.m.jd.com`。
2. 在京东 App 打开东东农场主页和主任务列表，再打开幸运转盘及其任务列表。需要分别保存两套活动页面环境；收到“凭据已保存”后可回到 Loon。
3. 先运行“农场完整任务查询”和“转盘完整任务查询”。日志列出全部任务、次数以及可执行／待领取／需手动的状态。
4. 使用下面的手动入口。不设置任何定时执行。

| 手动入口 | 用途 |
|---|---|
| 农场完整任务查询 | 查询主任务与补充模块，合并去重，显示全部任务 |
| 农场任务执行并领取 | 处理支持的浏览任务，并领取服务端已完成的奖励 |
| 农场只领取已完成奖励 | 包括你手动完成20次浇水后的待领奖励；不代替你浇水 |
| 转盘完整任务查询 | 查询当前转盘任务与剩余抽奖机会 |
| 转盘任务执行并抽奖 | 处理支持的浏览任务，再使用已有免费机会抽奖 |
| 转盘只用免费机会抽奖 | 不做任务，只使用已有免费机会 |
| 农场与转盘最近结果和进度 | 查询运行中进度或最近一次结果；完整列表见脚本日志 |

凭据保存到 Loon 的 `JD_FARM_TASKS_ACCOUNT_V1`，农场和转盘按活动分开。执行时可以读取“青龙任务接入”已保存的 `QL_BRIDGE_CREDENTIAL_V1`：同一账号且时间更新时，使用其中最新的 `pt_key`。不改写青龙、京喜或其他签到插件的数据。账号不一致时停止。

获取脚本只读取成功响应、保存本机模板，原样放行，不发送活动请求。签名在运行时用既有京东公开签名 SDK 生成，不重放抓包中的旧签名。无需在插件参数中粘贴 Cookie，不需要导入含个人信息的 HAR。

## 任务范围和水滴

**本版完全不浇水，不调用一键种植、自动种植或任何消耗水滴的接口。** 因此不会花掉你要留给“每日累计浇水20次”的800g水。该任务仍显示在完整列表里，标明“手动浇水，保留水滴”。你自己完成后可以手动运行“农场只领取已完成奖励”。如果水滴不足800g，脚本无法补足差额，也不会显示已经为你预留了800g。

自动处理类型为 `BROWSE_CHANNEL`、`BROWSE_PRODUCT`、`BROWSE_RTB`：按服务器给定的浏览项目和时长开始计时，等待后提交，重新查询任务进度，确认可领取后领奖。多次浏览任务按最新次数继续，单项最多30轮，单轮脚本最多约9分钟；剩余任务可再次手动执行。

这里的浏览采用脚本计时，不会实际打开 App 页面或播放视频。需要额外 App 回调的任务可能无法被认可，结果会明确显示待App确认；不会把等待时间当成任务成功。直播如果作为普通 `BROWSE_CHANNEL` 下发可按该类型处理；`EXTERNAL_BROWSE_BI_LIVE` 等需要独立App回调的类型保留手动。下单、邀请、分享、加组件、关注、订阅和小游戏任务全部列出，但不自动执行。

同一任务的识别使用 `pipeExt.assignmentId`，兼容大量任务共用 `taskId=-9999` 的新任务平台。补充模块与列表重复的任务去重，新任务名称和次数无需修改脚本。农场补充模块凭据缺失时提示重新打开主页，避免把部分列表当成完整列表。

转盘只在服务器返回已有抽奖机会、且不处于付费模式时调用抽奖接口。请求体只包含活动ID，机会为0立即停止。每次抽奖后复查次数，单轮最多50次；不购买次数、不扣水、不下单，也不进行邀请助力。

## 状态、失败与通知

日志记录当前任务序号、浏览剩余秒数、领取和抽奖结果。结束通知简短显示本轮复查确认的水滴或抽奖结果；查询通知提示到日志查看完整列表。

2026-10-22.2：请求之间至少间隔900毫秒；需手动和已完成的任务不逐项重复查询。日志和错误通知显示请求阶段、接口名及具体HTTP状态码，例如“开始计时失败：HTTP 403（apStartTaskTime）”。状态码用于进一步排查，不能仅凭HTTP异常认定是网络、签名或请求频率问题。

2026-10-22.3：提交任务、计时、领奖和抽奖前，通过京东官方 `https://cactus.jd.com/request_algo` 初始化服务端签名参数，再由官方SDK生成当前请求签名。该地址只接收SDK所需环境，不携带Cookie；每轮相同签名应用复用已取得的参数。初始化失败就停止，不再用本地回退签名提交活动动作。此修改针对“查询正常而开始计时HTTP403”的签名差异，手机端是否恢复需实际验证。

2026-10-22.4：增加失败响应诊断。在HTTP异常、响应无法解析或业务错误时，记录响应格式（JSON／HTML／文本／空响应）、长度、标准内容类型、数值错误码，以及是否出现签名、登录、访问限制等固定关键词；同时显示所用模板和签名开始前时间戳至发送的间隔。不保存原始响应、任意错误消息、Cookie、设备凭据、跟踪ID或响应头原文。关键词只说明响应里出现了相关词语，不能单独认定403由签名或网关导致。

2026-10-22.5：410包首次包含Loon脚本的实际失败请求。与409包对照发现，App会把响应头`x-rp-sdtoken: set;1800;<值>`里的会话值用于后续请求的`sdtoken` Cookie，原脚本始终复用各自模板中的旧值。现在只在本轮内接受京东API成功HTTP响应里的有效更新，并跨查询／动作模板使用最新会话；不改写手机保存的凭据、不上传或记录令牌值。相同签名应用的算法缓存不再因该Cookie轮换而重复初始化。日志只显示会话刷新次数和请求是否使用本轮会话。410中使用的签名Token和指纹与签名服务响应一致，离线重算主要签名摘要也一致，但这些仍不能证明京东认可全部请求环境。本版修正已观察到的会话更新缺项，是否解决403仍需手机实际验证。

**与青龙插件同时使用：暂时保持农场插件“获取农场与转盘凭据”关闭。** 两者的广泛响应匹配会发生冲突；Loon同一响应只运行首条匹配脚本。关闭获取保留现有农场凭据与全部手动入口，不影响本轮请求内部的会话更新。如需重新获取农场模板，可暂时禁用青龙插件，获取完农场凭据后关闭农场获取、恢复青龙。当前版本未改动该匹配规则。

当前手机实测：查询可用；2026-10-22.3初始化签名服务成功后，`apStartTaskTime`仍返回403，自动任务尚未跑通。409包中App成功完成“精选活动推荐”，进度1/7变2/7，待领取1次，未领奖；离线重建的任务内容和动态字段以外的表单参数与该成功请求一致。2026-10-22.4只补充诊断，不宣称修复403。更新插件后，运行原来的“农场任务执行并领取”一次，将失败日志里的“响应诊断”和“请求信息”发回即可；无需再抓App成功操作。仍保留已有动作记录，不重置失败结果待确认的任务、不自动重试；如果当天已无可尝试的任务，请次日再运行。

领奖返回数量和领取状态复查分别记录；水滴总余额变化不当成本轮奖励。网络中断、凭据变化、账号不一致、签名变化、跨零点或超时停止。提交前保存按账号和日期区分的动作记录，结果不明确的同一步骤不自动重试；请到App核对。农场与转盘共享执行锁，避免同时运行。操作活动时请勿同时在App执行同一任务或在其他脚本执行同一活动。

## 来源与验证

当前活动主列表28项、转盘列表9项是本次407／408包的观察值，实际以运行时服务器返回为准。覆盖任务列表不表示能自动完成所有任务。

接口证据：用户本机407／408抓包（不包含在公开文件中）。公开前端：[农场入口](https://pro.m.jd.com/mall/active/42HV4J3Q87B2xFQMJk81PCc1mEs3/index.html)、[农场页面脚本](https://storage11.360buyimg.com/ifloors/00043199/static/js/main.b153daeb.js)、[任务服务模块](https://storage11.360buyimg.com/ifloors/00043199/static/js/5.a18a7723.chunk.js)。

离线检查：`node test.cjs`。测试使用合成账号、模拟网络、两个既有官方签名SDK，校验任务列表与模块、重复ID、计时、领奖复查、重复提交保护、免费抽奖、保留水滴及凭据隔离。另用本机原始抓包离线回放凭据获取，未向京东发出真实账号任务请求。手机端实际运行仍需安装后验证。

本地构建：`python3 build.py`。构建只读取通用源码和经过校验的既有SDK，不读取HAR或个人凭据。
